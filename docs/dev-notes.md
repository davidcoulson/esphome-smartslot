# Dev notes

- Host tests: `make -C tests` (gcc, Unity, pthreads). Compile: `cd example && esphome compile smartslot-bench.yaml` (ESPHome 2026.10.0, venv `~/.venvs/esphome`).
- The vendored NUT files are byte-identical (`sha256sum -c components/smartslot/nut/SHA256SUMS`).
- Open risks: UART edge cases are only tested against the host fake serial, not a real UPS. `nutdrv` request slots: a caller that times out leaves the slot to the driver task. FSD latch is process-wide and is not cleared except by restart.
- INSTCMD / SET are queue-and-forget (`nutdrv_instcmd(..., 0)`): upsd replies OK once the request is queued to the driver task and the driver's result is only logged. That is NUT's own upsd semantics without TRACKING, and it keeps the single upsd task and the ESPHome loop from blocking on the serial link. Four requests can be pending at once; a fifth gets ERR.
- Inherited from the unmodified upstream driver, not fixed here: on a serial link `apcmicrolink.c` has no HID fallback, so a UPS that keeps answering the session handshake but never returns poll data is re-handshaked every poll, its cached values are republished and `dstate_dataok()` is called (`upsdrv_updateinfo`, the `microlink_reconnect_session` path). The shim cannot see whether a frame was a handshake or data, so it cannot mark that state stale without protocol knowledge. Fix belongs upstream (enforce `microlink_data_stale()` independently of handshake success); a real UPS that stops answering altogether does go stale and triggers a re-probe after 5 polls.
